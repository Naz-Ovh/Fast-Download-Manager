title: Command line
description: Download, resume and merge files from a terminal with the fdm command.
---

`fdm` runs the same download engine as the app, without a window. It is handy for scripts, servers and for
checking a link quickly.

<Callout title="Where to find it">
  From a source build: `cargo build --release -p fdm-cli` writes `target/release/fdm` (`fdm.exe` on Windows).
  The Windows installer, coming soon, puts `fdm.exe` in the install folder.
</Callout>

## Download a file: `fdm get`

```text
fdm get <url> [save-dir] [connections]
```

| argument | default | meaning |
| --- | --- | --- |
| `url` | | the file to download |
| `save-dir` | `.` (current folder) | where to save it |
| `connections` | `8` | parallel connections, up to `32` |

```powershell
fdm get https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.10.tar.xz D:\Downloads 8
```

Every second it prints the percentage, size, speed and how many connections are receiving.

- **Ctrl+C** stops the download and saves which chunks are done.
- **Run the same command again** to resume. It prints `resuming: ...` and fetches only what is missing.
- The progress is kept in a `.fdm-temp` folder inside the save folder until the file is complete.

From the repository you can also run `just get <url> [save-dir] [connections]`.

### See what the connections do

Set `RUST_LOG` to print how chunks move between connections and why a connection retries:

<Tabs items={['PowerShell', 'bash, zsh']}>
<Tab value="PowerShell">

```powershell
$env:RUST_LOG = "fdm_engine=debug"
fdm get https://example.com/file.zip D:\Downloads
```

</Tab>
<Tab value="bash, zsh">

```bash
RUST_LOG=fdm_engine=debug fdm get https://example.com/file.zip ~/Downloads
```

</Tab>
</Tabs>

## Download a DASH stream: `fdm dash`

```text
fdm dash <mpd-url> [id|best] [save-dir] [connections]
```

- **Without an id** it lists the stream: its qualities (id, size, bitrate, codecs) and the menu entries the
  browser button would offer.
- **With an id** (or `best`) it downloads that quality with its matching audio and merges them into one file.
  Ctrl+C stops; the same command resumes.

```bash
fdm dash https://example.com/stream.mpd
fdm dash https://example.com/stream.mpd best ./video 8
```

## Merge or convert local files: `fdm mux`

`fdm mux` joins video and audio files you already have, or rewraps a file, without re-encoding. It never touches
the network.

```text
fdm mux [--faststart] [--interleave] <video> [audio] <out.mp4>
fdm mux --ts <video.ts> <audio.ts|audio.aac> <out.ts>
fdm mux --mkv <video> [audio] <out.mkv>
fdm mux --probe <file>...
```

| command | does |
| --- | --- |
| `fdm mux video.mp4 audio.m4a out.mp4` | merge video and audio into one MP4 |
| `fdm mux in.ts out.mp4` | TS to MP4, or a fragmented MP4 to a normal MP4 |
| `fdm mux --ts video.ts audio.aac out.ts` | merge into one TS file |
| `fdm mux --mkv video.webm audio.webm out.mkv` | merge into MKV (WebM, MP4, TS or AAC inputs) |
| `fdm mux --probe file.mp4` | print which container a file really is |

Options for MP4 output:

- `--faststart` puts the index at the front of the file, so players can start before the whole file is read.
- `--interleave` alternates video and audio in about one-second steps.

An input can be several parts read in order: a folder (`parts/`, every file in name order) or a list file
(`@list.txt`, one path per line, the init part first).
